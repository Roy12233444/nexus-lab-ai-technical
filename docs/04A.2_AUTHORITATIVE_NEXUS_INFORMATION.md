# 5. ⚖️ Conflict Resolution & Provenance Register

### CONFLICT-001: NSEM Lifecycle Model vs. Granular Engineering Loop

- **Source A (Infographic/Visual):** `INSPIRATION → FORMALIZATION → VALIDATION → ENGINEERING → IMPACT`
- **Source B (Redesign Loop):** `Problem → Research → Architecture → Implementation → Experiment → Evidence → Validation → Technology`
- **Resolution:** Distinct levels of abstraction. Source A represents the macro institutional lifecycle (NSEM-Macro); Source B represents the micro engineering feedback loop (NSEM-Micro). Both are preserved in their respective contexts.

### CONFLICT-002: Ordering of Evidence and Validation

- **Source A:** `Evidence → Validation` (Evidence produces validation)
- **Source B:** `Validation → Evidence` (Validation criteria produce evidence)
- **Resolution:** Canonical causal ordering established: **Experiment → Evidence → Validation State**. Validation is the epistemic classification granted based on empirical Evidence.

### CONFLICT-003: Active Research Programs vs. Historical Project Portfolio

- **Active Canonical Programs (Overview Scope):** `NALA`, `AMP`, `RTA-GUARD`, `COSMOS`, and `Future Programs`.
- **Historical / Applied Portfolio:** `SynaptiCode`, `NexusAgri`, `PHANTAKSHA`, `EMMA`, `DeadReckoning` are cataloged as specialized applied prototypes or modular subsystems, not promoted to primary homepage programs.
