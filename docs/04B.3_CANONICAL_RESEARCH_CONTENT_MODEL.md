# 1. 🎯 Purpose & Epistemic Rules

This specification establishes the **canonical, machine-readable TypeScript content model** for the Nexus LAB AI Research Track, encoding the authoritative baseline established in `04B.2_AUTHORITATIVE_RESEARCH_INFORMATION.md`.

### Core Epistemic Principles:

1. **Strict Epistemic Fidelity:** The software data model reflects the four-axis truth system without manufacturing additional claims, inflating maturity, or collapsing multi-dimensional states.
2. **Project Independence by Default:** NALA, AMP, RTA-GUARD, and COSMOS are modeled as sovereign research vectors under the Nexus LAB AI umbrella. No runtime operational dependency, hierarchical management graph, or software coupling is assumed.
3. **Claim-Level Provenance:** Evidence is attached at the granular claim level with explicit claim IDs (`CLM-NALA-001`, `CLM-AMP-001`, etc.), preventing component-level proofs from over-generalizing to full program maturity.
4. **Quarantine Isolation:** Unsupported, unverified, or historical claims are isolated in a formal `quarantinedClaims` schema to ensure they cannot leak into the public user interface.

# 2. 🧬 TypeScript Architecture & Schema

The research data model resides in `src/types/research.ts` and consumes canonical epistemic tokens:

```typescript
export interface CanonicalResearchProject {
  identity: ResearchProjectIdentity;
  state: ResearchProjectState;
  provenance: ProvenanceRecord;
  architecture: {
    description: string;
    subsystems: ResearchSubsystem[];
  };
  evidenceRecords: ResearchEvidenceRecord[];
  limitations: ResearchProjectLimitations;
  publicSummary: ResearchProjectSummary;
  relationships: ResearchProjectRelationship[]; // Defaults to empty array []
}
```

### Four-Axis Decoupled Model:

- **MaturityState:** `CONCEPTUAL` | `SPECIFIED` | `PLANNED` | `IMPLEMENTED` | `EXPERIMENTAL`
- **EvidenceState:** `UNKNOWN` | `DOCUMENTED` | `REPORTED` | `OBSERVED` | `VERIFIED`
- **TemporalState:** `CURRENT` | `HISTORICAL` | `FUTURE` | `UNKNOWN`
- **PublicRelevanceState:** `PRIMARY` | `SUPPORTING` | `CONDITIONAL` | `INTERNAL` | `EXCLUDED`

# 4. 🛡️ Invariant Validation Rules

The programmatic validation engine in `src/lib/validation/researchContentValidation.ts` enforces the following hard invariants:

- **RULE-001 (Provenance Enforcement):** Every project and evidence record must contain explicit source IDs, authority tiers, and extraction timestamps.
- **RULE-002 (Verified Authority Requirement):** Any claim marked `VERIFIED` must be supported by Tier 1 (`CONSTITUTIONAL`), Tier 2 (`ENGINEERING`), or Tier 3 (`VERIFIED_EVIDENCE`) sources.
- **RULE-003 (Quarantine Wall):** Quarantined claim text cannot appear in `publicSummary.publicLead`.
- **RULE-004 (Project Independence):** No operational dependencies between research tracks are permitted without verified cross-system relationship records.
- **RULE-005 (Subsystem Isolation):** Bounded subsystem proofs (e.g. AMP Phase 1) cannot claim full parent program verification.
- **RULE-006 (Temporal Guard):** Projects marked with `FUTURE` temporal states cannot claim `IMPLEMENTED` maturity.
- **RULE-007 (Public Relevance Filter):** Entities marked `EXCLUDED` cannot have `PUBLIC_NOW` publication status.
