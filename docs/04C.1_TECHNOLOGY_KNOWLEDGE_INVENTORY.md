## 0. Methodology Note — Read This First

The original task spec assumes the executing agent (Claude Code) has direct filesystem access to your repositories, Obsidian vault, config files, and prior technical discussions, and can perform live source discovery against them.

**This document was not produced that way.** It was produced in a chat environment with no access to your actual repos, your `E:\Nexus_LAB_Obsedian_Brain\` vault, or any local files — only to accumulated conversation-memory records built up across prior sessions with you (project summaries, architecture notes, and decisions you've described over time).

That has one direct consequence for how to read this document: **every entry below has Evidence State = `DOCUMENTED` (asserted in prior conversation, not independently verified) unless otherwise noted.** None are `VERIFIED` in the sense of "Claude read the source file and confirmed it." Where a claim included a specific external evidence anchor (e.g., a GitHub repo), I've flagged that separately.

This is not a defect to route around — it's exactly the distinction Section 5 of the spec asks for, and it's the most important fact in this inventory. Treat this as **Iteration 0**: a structured, honest first pass over what you've told this system about your own stack, organized so that a future pass — run by an agent with actual repo/vault access — can upgrade each entry from `DOCUMENTED` to `VERIFIED` or `CONTRADICTED` rather than starting from nothing.
