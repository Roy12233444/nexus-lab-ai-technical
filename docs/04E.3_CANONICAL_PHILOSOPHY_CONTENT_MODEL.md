## 3. Epistemic Validation Engine (`validatePhilosophyContent`)

The validation engine in `src/lib/validation/philosophyContentValidation.ts` enforces eight strict invariant rules:

| Rule Code  | Invariant Rule                      | Operational Enforcement Mechanism                                                                                       |
| ---------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `RULE-001` | **Provenance & Claim Linkage**      | Every claim, hypothesis, and principle must reference an existing valid concept ID in the registry.                     |
| `RULE-002` | **Historical Anachronism Firewall** | RegEx filter scanning definitions and claims for anachronistic patterns asserting ancient texts invented modern AI.     |
| `RULE-003` | **Multi-Layer Separation**          | Verifies non-empty and strictly distinct classical definition, philosophical question, and Nexus interpretation fields. |
| `RULE-004` | **Non-Claims Requirement**          | Every public primary and supporting concept must include mandatory explicit negative bounds (`nonClaims[]`).            |
| `RULE-005` | **Hypothesis Status Invariant**     | AI hypotheses must remain explicitly designated as `HYPOTHESIS` or `CONJECTURE`.                                        |
| `RULE-006` | **Mapping Integrity**               | `DIRECT` mappings are strictly gated to verified implementations (`CHAITANYA / SAPTACORE`, `RTA-GUARD` pre-flight).     |
| `RULE-007` | **Evidence Decoupling**             | Prohibits asserting `VERIFIED` production benchmarks without independent empirical proof.                               |
| `RULE-008` | **Quarantine Firewall**             | Prohibits quarantined claim IDs from leaking into active public claims or public selectors.                             |

## 4. Public Selectors API

Downstream UI components are prohibited from accessing raw dictionary keys or manually parsing philosophy data. They must consume public selectors:

1. `getPublicPrimaryConcepts()`: Returns the 8 flagship primary concepts with their multi-layer metadata, hypotheses, and non-claims.
2. `getPublicSupportingConcepts()`: Returns the 4 supporting contextual concepts.
3. `getDeepResearchConcepts()`: Returns the 4 deep research concepts reserved for technical whitepapers.
4. `getPublicPhilosophyPrinciples()`: Returns the 8 foundational principles sorted sequentially.
5. `getAllPublicClaims()`: Returns all 12 verified public claim records.
6. `getQuarantinedClaims()`: Returns the 5 quarantined assertion classes for public firewall inspection.
