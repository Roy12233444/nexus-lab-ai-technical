## 4. Epistemic Evidence Visual Constraints

To prevent visual inflation, each evidence tier possesses a strictly defined visual style:

1. **`VERIFIED`**: Emerald badge (`bg-emerald-500/10 text-emerald-700 dark:text-emerald-400`). Reserved strictly for formal proofs and automated passing tests.
2. **`REPORTED`**: Blue badge (`bg-blue-500/10 text-blue-700 dark:text-blue-400`). Empirically observed in controlled testbeds.
3. **`DOCUMENTED`**: Slate badge (`bg-slate-500/10 text-slate-700 dark:text-slate-400`). Formally specified in architecture blueprints.
4. **`EXPERIMENTAL`**: Amber badge (`bg-amber-500/10 text-amber-700 dark:text-amber-400`). Active laboratory prototypes under test.
5. **`THEORETICAL`**: Purple badge (`bg-purple-500/10 text-purple-700 dark:text-purple-400`). Mathematical/conceptual formulation with zero production code.
6. **`UNVERIFIED`**: Rose badge (`bg-rose-500/10 text-rose-700 dark:text-rose-400`). Open systems bottlenecks.

## 5. Responsive Behavior & Accessibility Contracts

- **Desktop (1024px+)**: High-density multi-column layouts, expanded data tables, interactive side-by-side dossiers.
- **Tablet (768px–1023px)**: 2-column stacked grids, horizontally scrollable data matrices with sticky headers.
- **Mobile (<768px)**: Single-column vertical flow, swipeable cards, condensed matrix viewports.
- **Color Independence**: Every state, pressure vector, and evidence level communicates status via text labels and icons, ensuring full WCAG AAA accessibility for colorblind visitors.
- **Screen Reader Parity**: Every diagram and flow graph specifies a detailed `screenReaderSummary` attribute.
